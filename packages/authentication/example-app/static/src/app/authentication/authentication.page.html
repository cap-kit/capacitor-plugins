Before you run Real provider credentials are required — placeholders only, never real secrets

Google

Web: OAuth web client (server client) whose id ends in apps.googleusercontent.com; register the host origin as authorized JavaScript origin and redirect URI. Native: googleServerClientId from the Google Cloud Console.

Apple

appleClientId = Apple Services ID (Web popup) or bundle id (iOS). iOS needs the Sign in with Apple capability + team signing; Android uses a WebView OAuth flow; Web loads appleid.auth.js from Apple's CDN on the host page.

Facebook

facebookAppId + facebookClientToken. iOS Info.plist: FacebookAppID, FacebookClientToken, FacebookDisplayName, URL scheme fb{{ '{' }}APPID{{ '}' }}. Android host strings.xml: facebook_app_id, facebook_client_token, fb_login_protocol_scheme.

Facebook key hash (Android)

Sign-in only succeeds when the build's development key hash is registered with Meta (keytool -list -v -keystore ~/.android/debug.keystore — debug and release hashes differ). Unregistered key surfaces as INIT_FAILED (code 1349094).

Missing or blank config never crashes the demo

Absent keys reject with INIT_FAILED, blank values with INVALID_INPUT — both render in the error panel below.

Sign in

Scopes are omitted so the plugin applies its defaults (google: openid email profile · apple: name email · facebook: public_profile email). Sign-in is single-flight per provider — the button disables while a flow is in flight.
